Your own proxy

The safest option: your real provider API key never touches the browser at all — it lives only on a small server you control, which BerryStudio calls instead.

EndpointWhatever URL you enter — your own server
Needs a keyNo key in the browser; your server holds the real key and forwards the request
ContractThe same one this project's server/billboard-proxy/worker.js reference implementation already uses — unchanged since before BYO-AI existed

Setup

  1. Deploy a small proxy (BerryStudio's repo ships a working Cloudflare Worker reference at server/billboard-proxy/worker.js you can adapt or deploy as-is).
  2. In BerryStudio: Settings → AI Provider → choose Your own proxy, and enter your deployed URL.
  3. Test Connection to confirm it's reachable and responding correctly.
Choose this option if you don't want an API key ever present in browser memory or dev tools, even briefly — every other provider here does hold your key client-side (session-scoped by default, see the security model).

الخادم الوسيط الخاص بك

الخيار الأكثر أمانًا: مفتاح API الحقيقي لمزوّدك لا يلمس المتصفح إطلاقًا — يعيش فقط على خادم صغير تتحكم به، ويستدعيه BerryStudio بدلًا من ذلك.

نقطة النهايةأي عنوان تُدخله — خادمك الخاص
يحتاج مفتاحًالا مفتاح في المتصفح؛ يحتفظ خادمك بالمفتاح الحقيقي ويمرّر الطلب
العقد (Contract)نفس العقد الذي يستخدمه بالفعل التنفيذ المرجعي server/billboard-proxy/worker.js في هذا المشروع — دون تغيير منذ ما قبل وجود ميزة "استخدم ذكاءك الاصطناعي"

الإعداد

  1. انشر خادمًا وسيطًا صغيرًا (مستودع BerryStudio يشحن تنفيذًا مرجعيًا عاملًا لـCloudflare Worker في server/billboard-proxy/worker.js يمكنك تعديله أو نشره كما هو).
  2. في BerryStudio: الإعدادات ← مزوّد الذكاء الاصطناعي ← اختر الخادم الوسيط الخاص بك، وأدخل عنوان النشر الخاص بك.
  3. Test Connection للتأكد من أنه قابل للوصول ويستجيب بشكل صحيح.
اختر هذا الخيار إذا كنت لا تريد لمفتاح API أن يوجد أبدًا في ذاكرة المتصفح أو أدوات المطوّر، ولو للحظة — كل مزوّد آخر هنا يحتفظ بمفتاحك على جهة العميل (بنطاق الجلسة افتراضيًا، راجع نموذج الأمان).
